# SkellCore shared preset distribution — phase 1

Customer experience target: install a compatible plugin once, browse the local cache even offline, check the signed catalog on a worker, fetch only changed immutable objects, refresh catalog metadata without loading a rack or changing a session. Preset data and artist covers are not executable updates. Engine changes still need a new compatible build.

Implemented portable PresetFeed.h: mandatory signature verification callback, strict bounded manifest parser, product/channel binding, ABI guard, monotonically increasing generation, same-generation equivocation rejection, content hash and semantic validation, deduplicated cache reuse, commit-after-all-objects. The adapter must enforce HTTPS to a fixed owner-controlled origin, no redirects, bounded responses/timeouts, pinned public key, native package and artwork validation, per-channel caches, process-wide lock plus atomic snapshot compare-and-swap. It must not run on the audio thread. Never overwrite user files or force-reload existing instances. Until the real adapter is implemented and verified, the portable contract is not a working customer updater. No deployed endpoint or release key exists in this change.

Publisher tools/preset_feed.py builds a new static feed folder using the existing Sound Match R48 private catalog and validator. RSA SHA-256 PKCS#1 v1.5 signs exact manifest bytes; signing key remains private, native adapter pins corresponding public key. Use separate private testing and customer release endpoints. Release selects latest explicitly native-approved revision, retaining prior approved revision when a trial is staged. No automatic promotion from listening feedback. Only publish the generated manifest.tsv, manifest.sig and objects/; never the original catalog, private audio, learned models or key. Publish immutable objects first, then manifest and signature; mismatch during transition fails closed. For intentional rollback publish a NEW generation with the previous approved payload, never decrement generation. Cache snapshot remains usable if offline, subject to native validation. No automatic deletion or license/paywall integration.

Wire format UTF-8/LF: header SKELLFEED1, product ID, channel, generation, separated by tabs. Rows: preset ID, artist ID, artist display name, preset title, main/adlib, minimum native ABI, SHA256, exact byte count, artwork SHA256 or '-', artwork count (0 if absent). Objects addressed by hashes under objects/<sha>.skellpreset or .png. No remote executable code or arbitrary URLs. Limit 1000 entries, 1MiB manifest, 4MiB preset, 8MiB image, 128MiB new objects per sync. Metadata titles are not IDs. Native compatibility ABI is explicitly set by publisher only after real plugin verification.

Local evidence: C++17 warnings-as-errors portable regression executable passed; test covers initial install, cache reuse, individual update, rollback, duplicate/path validation, signature failure, ABI rejection, wrong object hash, offline, storage failure, semantic rejection, cache repair and channel binding. Authentication/digest/storage in this test are mock adapters, not native crypto/HTTP. Real OpenSSL test with temporary RSA key and 12 private R48 native trial packages produced verified signed trial feed, verified object hashes, rejected tampered manifest and refused a release containing only trials. Synthetic approved-then-trial test preserved approved revision. Private data and temporary keys not committed. Next gate: actual native HTTPS, pinned-key verification, filesystem transaction, browser integration, signed deployment, Windows VST3 and FL Studio/Quick4. No new customer build claimed.
