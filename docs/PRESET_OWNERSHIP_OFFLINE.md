# Shared preset ownership and offline contract

Phase 2 of the signed feed. No network access from audio processing or project restore. The official cache and personal data are separate by design. On first launch without a valid cache use bundled factory presets; while offline use authenticated cached official data. Missing, incompatible or damaged cached entries fall back to the corresponding bundled preset if available, otherwise surface unavailable. Never substitute a different sound in a recalled project. The UI must show the actual selected revision and fallback status. Manual check works when automatic checks are disabled; no network when known offline. Notification/history flags are stored locally, not read from the feed.

PresetOwnership.h provides a worker/control-thread-only offline resolver with mandatory manifest authentication, product/channel/ABI checks, object digest and native validation. Explicit revision lookup uses authenticated archived snapshots. Personal saves use a distinct ID namespace, refuse implicit replacement, and own complete native payloads. Pinned revisions and startup defaults store independent full copies; a later edit, official update or removal of a cache object cannot mutate them. Default applies only when explicitly creating a fresh instance, never on project recall. Embedded project-state helper returns the exact bytes or an error; host serializer and backward compatibility tests remain required. A local bounded binary codec persists preferences, personal, pinned and default copies; transactional edit uses adapter CAS and rejects corrupt stores without resetting them. Local state cap 64 MiB, 1000 personal and 1000 pinned IDs, 4 MiB per payload. Host must surface capacity/errors, preserve existing user library files and use correct native validation; this is additive, not a migration or replacement of existing .skellpreset files. Provenance identifies the source revision, not the hash of a locally edited payload. No automatic garbage collection. History lookup requires archived signed snapshots; native adapter should archive prior snapshots on successful commit when history enabled. Pinned bytes remain independent even if history is disabled. UI, notification scheduling, history retention, host integration of per-product filesystem store, pinned public-key crypto and HTTPS remain integration work. No real DAW state migration or plugin UI changes.

Host-independent distribution: deploy only signed manifest/signature and content-addressed static objects to a trusted HTTPS endpoint. Cloudflare Pages static hosting is a reasonable starting point; R2 or existing compatible hosting are alternatives, subject to terms, availability and quotas. No owner-operated server, account system or database needed for public packs. Private trial/paid feeds need separate access control; signatures authenticate content, not entitlement. Public artifacts must be intentionally public. No hardcoded credentials in plugin. No endpoint configured, no hosting account created. Without hosting, bundled and cached/user presets work locally; new remote updates cannot arrive. A future transport adapter may support explicitly approved mirrors with the same pinned trust and generation checks.

Local exact-source GCC C++17 ownership and existing 16-scenario feed regression tests passed with warnings as errors; ownership test also passed ASan/UBSan. Test adapters are in-memory mock authentication/digest/cache/CAS, not production crypto, disk or actual DAW. Tests cover offline first launch, cache reuse, missing/corrupt cache, incompatible ABI, signature failure, update without ownership mutation, explicit save replacement, independent default, pin surviving cache deletion, explicit revision lookup, embedded recall, check settings, codec round trip and corrupt/truncated payload rejection, failed local transaction. JUCE fetch blocked by DNS; no native VST3, Quick4 or host validation claimed. No merge.

## Local disk adapter

PresetLocalStore.h adds a per-product directory chosen by the host, separate from official cache and existing user files. Cooperative OS file lock plus byte-level CAS rejects stale writes; a flushed temporary file and same-directory rename replace the committed snapshot. Empty existing files, nonregular state files, corrupt codecs and failed reads are not treated as missing state. Interrupted temporary files are ignored on read and recovered under lock on the next successful write. No audio-thread access. Host must keep the directory local, use the same canonical directory across instances, report stale-writer conflicts, retain existing user library files, and handle explicit backups and recovery. No claim of protection from arbitrary same-user filesystem modification or all power-loss cases. Tested on Linux with two concurrent store instances, reopening from disk, interrupted temp file, corrupt and empty state, stale CAS and independent default. Warnings-as-errors and ASan/UBSan passed. Windows file lock/replacement branch added but not locally executed. No actual plugin connection or UI yet.
