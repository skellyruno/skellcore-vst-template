# Experimental signed entitlement verifier

Independent defensive design, not derived from a protected vendor implementation. OpenSSL 3.x EVP Ed25519 one-shot signature verification; https://docs.openssl.org/3.4/man7/EVP_SIGNATURE-ED25519/ (OpenSSL Apache-2.0). No new required dependency; isolated opt-in build/test only, no Core.h inclusion. No production licensing, server, signing utility, public keys, or host changes. Antares documents account-managed computer/iLok activation, but no claim of its internal mechanism or stronger protection: https://help.antarestech.com/hc/en-us/articles/41076506074772-How-To-Activate-Your-License-With-Auto-Tune-Central .

## Wire format and trust model
180 bytes, exact length. Signed payload 116 bytes followed by 64-byte Ed25519 signature. Magic SKLLIC01 (8), key ID (4, big endian), product (16), license ID (16, authenticated but not interpreted by this verifier), installation binding (32), feature mask (8), issue time (8), not-before (8), expiry (8), monotonic sequence (8); all integers unsigned big endian. Time is caller-supplied trusted UTC seconds; no implicit local time read. Trusted public keys supplied by application configuration, max 16; no private signing key in client. Exact product/binding checks, issue <= start < expiry, inclusive start/exclusive expiry, minimum sequence and allowed feature mask; all failures return zero grants. No mutable global state, no network, no file reads. OpenSSL can allocate and lock; never call from audio callback.

## Release hardening still required
Server-side entitlement issuance, secure signing-key storage/rotation and revocation, signed update metadata, Windows/macOS code signing, installation ID with privacy-preserving storage, OS-protected trusted time and monotonic sequence storage, per-license identity policy, offline expiry and recovery policy, authenticated transport. Caller-provided minimumSequence is not a persistent anti-rollback system. A copied token plus cloned binding or compromised client is not solved by signatures. No anti-debugging, packer, executable mutation, DRM bypass or hidden host behavior. Do not silently mute audio, alter existing project state, or introduce time/network/disk work on audio thread; publish immutable validated state off-thread with explicit user-facing licensing UX. Treat local client as untrusted; no claim uncrackable or stronger than iLok. Independent threat model/review and actual Windows/macOS testing required before adoption.
